# طلبات عروض الأسعار الآمنة — الإصدار v0.9

**المشروع المستهدف حصريًا:** Supabase **Saeed Naji** `afrvoshsiqartsketiuv` والمستودع `Saeed-Naji/Saeed-naji-card`.
لا يُغيّر هذا التطوير أي شيء في قاعدة Flower Light القديمة، ولا يحذف جداول مشروع Saeed السابقة.

## ما تم إنجازه

1. أُضيف جدول `corp_quote_intake_log` لتتبع عدد الطلبات دون حفظ محتوى الرسائل، وهو غير مكشوف للزوار (RLS).
2. دالة `corp_submit_quote_secure` تعمل بدور `service_role` **فقط**، وتتحقق من المنتجات المنشورة والكميات، وتعيد بناء أسماء المنتجات وأكوادها من قاعدة البيانات بدل الثقة بمدخلات المتصفح.
3. تم وضع حد قدره **3 طلبات للوسيلة الواحدة خلال ساعة**، و**120 طلبًا لكل الموقع خلال ساعة**. تُحفظ بصمة HMAC للاتصال بدل حفظه في سجل الحدود. لا تُحذف سجلات الحدود تلقائيًا في هذا الإصدار؛ يجب تحديد سياسة احتفاظ وتنظيف دوري قبل الاعتماد التجاري.
4. وظيفة Edge Function باسم `corp-submit-quote` مع إعداد `verify_jwt=false`، لكنها **ليست مفتوحة بلا حماية**: تتحقق من نطاق Saeed، وطلب POST، وحد حجم الجسم، وCloudflare Turnstile على الخادم، بما في ذلك `hostname` و`action=quote_submit`. عند غياب السر، ترفض جميع الطلبات بحالة `not_configured` (503).
5. تم تجهيز نموذج طلب عرض سعر من قائمة المنتجات، مع اسم العميل ووسيلة التواصل والشركة والملاحظات، وموافقة صريحة على استخدام البيانات للرد فقط. لا يعرض زر الإرسال الفعلي قبل تهيئة Site Key العام.
6. لوحة المدير الحالية تعرض الطلبات من `corp_quote_requests` وتتيح تعديل حالتها للمالك المعتمد فقط.

## خطوات التفعيل المطلوبة

**لم تُفعّل خدمة استقبال الطلبات للزوار بعد.** يلزم إكمال الآتي على حسابات المشروع الجديد:

1. ادخل إلى [لوحة Cloudflare Turnstile](https://dash.cloudflare.com/) وأنشئ Widget للنطاق `saeed-naji.github.io` الخاص بالموقع الجديد. خذ Site Key (عام) وSecret Key (سري).
2. افتح [Supabase Edge Function Secrets — مشروع Saeed](https://supabase.com/dashboard/project/afrvoshsiqartsketiuv/settings/functions) وأضف السر باسم **`TURNSTILE_SECRET_KEY`**. لا تضعه في GitHub أو محادثة عامة أو `VITE_`.
3. في GitHub للمستودع `Saeed-Naji/Saeed-naji-card`: Settings → Secrets and variables → Actions → Variables، أضف **`CORP_TURNSTILE_SITE_KEY`** بالقيمة العامة فقط.
4. شغّل إعادة نشر GitHub Pages من Actions → `Deploy independent corporate React preview` → Run workflow (أو عبر commit جديد).
5. اختبر نموذج الطلب الحقيقي بعد إضافة منتج واحد على الأقل، باستخدام اختبار Turnstile حقيقي صالح، وتحقق من إنشاء صف `corp_quote_requests` في قاعدة Saeed ومن ظهوره داخل لوحة المالك.
6. اختبر رفض الرمز غير الصحيح، والتكرار السريع، وعدم قدرة الزائر على قراءة طلبات عملاء آخرين.
7. **قبل استقبال بيانات حقيقية:** أكمل سياسة الخصوصية المناسبة (الاحتفاظ والحذف ووسيلة الاتصال والغرض) ثم اعتمدها قانونيًا؛ لا تفترض أن هذا الملف سياسة خصوصية منشورة. أنشئ تنظيفًا دوريًا لسجلات `corp_quote_intake_log`.

## الضوابط والقيود

- لا يوجد مفتاح `service_role` أو Turnstile Secret في GitHub. يستخدم الـEdge Function متغيرات Supabase الخادمية فقط.
- بيانات الزوار لا تُرسل من النموذج إلا بعد موافقة واضحة واجتياز Turnstile.
- تحوّل دالة Postgres كل مجموعة منتجات إلى أسماء وأكواد حقيقية، ولا تقبل منتجات مخفية أو غير موجودة.
- يرفض الـEdge Function الطلب إن كان مفتاح Turnstile غير متوفر؛ لا يوجد مسار بديل يتجاوز التحقق.
- لا تختبر ببيانات عملاء حقيقية قبل تأكيد الخدمة وسياسة الخصوصية.
- سجلات `corp_quote_intake_log` تحتفظ ببصمة HMAC فقط، لكنها قد تتراكم؛ ينبغي تنظيفها بعد اعتماد سياسة الاحتفاظ.
- الحماية تعوق الإساءة لكنها لا تضمن منع كل الرسائل المزعجة، ولا تحل محل المراقبة والإنذارات.
- وظيفة `manage-admin-account` القديمة والجداول الـ15 وملفات Storage القديمة لم تُمس.
