# قاعدة البيانات الجديدة لموقع Saeed Naji — حالة التنفيذ

**المشروع المعتمد حصريًا: `afrvoshsiqartsketiuv`** (Saeed Naji).
**لا يتبع مشروع Flower Light الموجود في Basair-Alkhalij.**

## نتيجة التنفيذ

- أُنشئت بنجاح جداول `corp_products`، `corp_admin_members`، `corp_business_info`، `corp_quote_requests` داخل مشروع Saeed في Supabase بتاريخ 2 نوفمبر 2026.
- الهجرة المسجلة: `saeed_corporate_initial_tables_and_rls`.
- سياسات RLS فُعّلت على الجداول الأربعة، والتحقق بدور `anon` نجح: يستطيع مشاهدة 4 منتجات تجريبية ظاهرة، ولا يمكنه إضافة مدير أو منتج أو رؤية الطلبات.
- أُدرجت 4 منتجات DEMO فقط؛ لم تُنسخ المنتجات والعملاء القدامى.
- بيانات المنشأة موجودة بوضع غير منشور، ولا يوجد مدير معتمد حتى الآن.

## الخطوات العالقة

**جداول النظام السابق الـ15 لم تُحذف.** رفضت أداة التنفيذ عملية المسح الشامل، ولم نكرر الحذف بوسائل بديلة. يجب النسخ الاحتياطي أولًا ثم مراجعة وتنفيذ ملف التنظيف المُعدّ بشكل محدد يدويًا في مشروع Saeed.

الملف `FINAL_REMOVE_LEGACY_SAEED_REVIEW_FIRST.sql` مصمم ليحذف فقط الكائنات القديمة المدرجة بالاسم ويُبقي جداول `corp_*`. الملف القديم `RESET_SAEED_PUBLIC_FOR_CORPORATE.sql` أُلغي وظيفيًا لمنع مسح الجداول الجديدة خطأً.

**الحالة التفصيلية والخطوات الآمنة:** [STATUS_AND_FINISH_SAEED_RESET_AR.md](STATUS_AND_FINISH_SAEED_RESET_AR.md).

## ما يلزم لتفعيل لوحة المدير

- تحديد حساب المدير الصحيح من Auth ثم إضافته يدويًا إلى `corp_admin_members` بعد مراجعة هويته.
- إنهاء تنظيف الخدمات والدوال القديمة وفحص Security Advisors؛ في المشروع حاليًا تحذيرات أمنية متعلقة بالنظام السابق.
- وضع `CORP_SUPABASE_URL` و`CORP_SUPABASE_PUBLISHABLE_KEY` العموميين فقط في GitHub Actions Variables للمستودع الجديد.
- اختبار Login، وRLS، ورفع/تعديل المنتجات والإعدادات قبل نشر الإدارة.

**لا تعرّض service_role أو secret key للمتصفح أو GitHub.** حتى الآن لم نصل لوحة الإنتاج الفعلية، ولم ننفذ أي SQL على قاعدة مشروع Basair-Alkhalij القديم.
